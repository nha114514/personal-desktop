## B. 桌面操控、视觉和工作台返工

1. 统一模型侧 Windows-MCP 与 UI 的 PersonalDesktopControl。用现有服务/扩展共享一个执行管理入口，避免两套进程、队列、停止状态。
2. 当前 provider 的 guard 返回 undefined 没有执行 mutex。换用仓库支持的异步 around-dispatch 或工具执行包装，真实接入 FIFO 队列、取消信号、停止、恢复和安全回收。停止需同时约束模型与界面调用；待执行 promise 被拒绝；已停止不自动恢复。
3. 按真实 tools/list 和参数分类鼠标键盘、切换/激活窗口等会争用桌面的动作；桌面观察与动作仅主模型可调用，子代理不得切焦点或间接执行桌面操作。用假 MCP 覆盖并发、队列顺序、两入口共用停止及取消重开，不通过真的随机点击测试并发。
4. 真实传递图像：修复 Gemini 会员 CLI/Codex formatter 与请求构造丢弃 image 的问题，按已装官方 CLI 支持的协议执行。不能将文件名、base64 文本、图像路径当成视觉输入。不支持的路由明确报告能力限制，避免静默丢图。
5. Screenshot 的目标、范围和来源必须清晰；Personal Desktop capturePage 只算自身应用截图，不能把外部桌面截屏失败改成成功。采用公共宿主实际支持的目标窗口/桌面截图，限制条件真实报告。
6. 工作台绑定既有真实会话、子任务、工具调用、文件版本、资料与证据，支持在正确项目下续作。记录外部声明为待核实、记录证据、最终判定分开；不要新建平行 agent runtime。
7. 限制允许的字段和状态转换。存在必要未验证项、失败项或失败检查时不能单凭 judgment: passed 自动 accepted。用户人工确认与主模型判定应有真实来源，不能由外部报告或任意 patch 伪造。
8. 技能使用必须来自真实加载与执行记录。保留迁移目录/resources 和用户修改，按任务阶段给授权叶子模型实际加载规则和工具，独立复核由主模型派发另一真实叶子。
